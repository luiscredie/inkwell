────────────────────────────────────────────────────────────
THE ERROR

  Root.renderVals(): Cannot set properties of undefined (setting 'inkExert')

Red box, no app, on opening a replay.

THE CAUSE — my bug, from V14

In V14 a test caught that "Your turn begins" was not recognised, so I widened the
turn regex in three places to accept "Your". But inside simulateReplay the actor is
not resolved by that same code — it goes through a helper, P(), which still knew
only "You":

  const P=(x)=>x==='You'?1:(x==='Opponent'?2:+x);

Given "Your", P fell through to +x and returned NaN. So S[NaN].inkExert = 0 threw
on the very first turn marker.

The shape of the mistake is worth naming: widening a RECOGNISER without checking
every CONSUMER of what it recognises. Before V14 that line was ignored and nothing
broke. After V14 it was recognised and handed to a mapper that could not translate
it. I fixed the two assignments using m[2]==='You' and never looked for a third
consumer written differently.

────────────────────────────────────────────────────────────
THE FIX

P() now accepts any form starting with "You" and returns null — never NaN — for
anything that is not player 1 or 2.

simulateReplay also gained slot(p), which hands back a throwaway object for an
unknown actor. Three writes were indexing S directly with P()'s result; none do
now. A malformed event costs THAT EVENT, not the whole screen. A third-party log
with one odd line should not be able to take down the app.
