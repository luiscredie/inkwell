LIVING INK
The GLSL is the one shipped in the pack, maths untouched. I changed exactly one
constant: charcoal from vec3(0.06,0.07,0.09) to vec3(0.039,0.047,0.063), which is
the #0a0c10 the same guide specifies — the original was calibrated for #0e0e0e and
would have sat visibly apart from the surface behind it.

Plain WebGL, no dependency. Optimisations the guide did not ask for but that are
not optional in an app also running a portfolio optimiser:

  - renders at HALF RESOLUTION with DPR pinned to 1. It is a slow blur; nobody can
    see the difference, and it cuts about 75% of the pixels.
  - mediump instead of highp
  - the loop STOPS when the tab is backgrounded (document.hidden)
  - powerPreference: 'low-power'
  - cancelAnimationFrame and resize-listener removal when the canvas unmounts

PERFORMANCE MODE
Bottom-right pill, as in the mock. Default OFF (effects on), per the spec,
persisted to localStorage.

Three conditions force the static background REGARDLESS of the toggle:
prefers-reduced-motion, screens <= 860px, and no WebGL context. That last one
matters — without it, a machine with WebGL disabled would get an empty black
page instead of a background.

The fallback is not a flat colour: two radials, amethyst and gold, keeping the
depth at no GPU cost.

THREE DEVIATIONS, ALL DELIBERATE

FONT. The guide says "Inter or a clean Apple-ish Sans-Serif". It is staying Plus
Jakarta Sans, which fits that description and is the exact font you pointed at as
the one you like ("Atividade de Partidas"). Following the document to the letter
here would mean overriding your stated preference. Say the word if you want Inter.

THREE.JS VORTEX. Not implemented. That is roughly 600KB of library for a
decorative element, in a single file already at 483KB. The shader delivers the
"living artifact" feel with zero dependencies. If the vortex is essential it can
go in — but lazy-loaded, and only when perf mode is off.

LANDING HERO. The "Illuminary" mock is a presentation page: title, description,
two CTAs. The app's Overview is a dashboard for someone already signed in, and
putting a marketing hero above it would push the real data below the fold. The
400px coin went to ONBOARDING instead, which is the actual landing moment.

A BUG I CAUGHT IN THIS PACKAGE BEFORE SHIPPING IT

Adding the shader cleanup gave the class a SECOND componentWillUnmount. In JS the
last definition silently wins, so the existing
componentWillUnmount(){ this.unbindModalKeys(); } would have stopped running —
leaking modal keyboard handlers on every unmount.

Fixed by naming the shader cleanup releaseInkShader() and calling it from the
existing lifecycle method. One componentWillUnmount, both jobs.
