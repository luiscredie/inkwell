WHAT I FOUND IN THE DATA BEFORE BUILDING

site/data/meta-decks.json has no tournament data at all. Three lists, all
source_type "community_popular", every tournament_result null, confidence
0.61-0.66 labelled community_reference, all three work_in_progress. The file's own
selection_policy says it plainly: popularity signal, not tournament proof.

So there is no tier language anywhere in this section. It is called "Popular
community lists", and a standing notice says the data carries no tournament
results. That notice disappears only if a deck gains a real tournament_result —
there is a test for exactly that, so it cannot rot into a lie.

The file is also NOT in data-manifest.json, so unlike prices and cards it is not
checksum-verified. It loads as optional and never fatal, trying two paths, outside
loadArtifact entirely. A missing file simply means the section does not appear.

────────────────────────────────────────────────────────────
WHAT THE SECTION DOES

Per list, against your actual collection:
  - coverage: reprints pooled by identity, foils counted, and owning MORE than a
    list asks for does not inflate the percentage
  - cost to complete, from your own price data, with cards that have no real
    price counted and reported rather than silently treated as free
  - what you are missing, per line, sorted by copies needed
  - which of YOUR decks shares the most cards with the list
  - substitutions drawn only from cards you own

Substitutions match ink, cost and type, two at most, with the caveat shown next to
them: they are not strategy equivalents. If you own nothing that matches, you get
nothing — an empty result beats a guess.

────────────────────────────────────────────────────────────
AN i18n TRAP WORTH KNOWING ABOUT

English values like 'How to play:' and 'You own instead:' make the i18n key
extractor in your test suites read "play" and "instead" as dictionary keys, which
produced a false EN/PT parity failure. I removed the inner colons (the template
presents these as headings anyway). Rule for future strings: never put "word:"
inside a translation value.
