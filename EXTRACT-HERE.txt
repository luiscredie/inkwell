WHAT M2.3 ADDS

Deck-first, in the Decks view, above the deck grid. One collapsible block per
deck. Each block lists that deck's cards with owned copies, allocation, and a
mark: ✓ covered, △ shared, × short. Contested rows are tinted; short rows sort to
the top. Default shows only shared cards; "Show all cards" opens the deck's full
inventory.

RECOMMENDATION — only where there is a real conflict (demand exceeds stock). The
named deck is the one the plan actually favours, and the reason is read off the
plan state: you pinned it, it finishes with these copies, these copies complete it
outright, or it needs the fewest copies. Where there are enough copies for
everyone, no recommendation appears — there is no decision to make, and inventing
one would be noise.

REVERSE PATH — you left this to me. Each contested card is a button; opening it
lists the competing decks with allocated/needed, plus the recommendation. Not a
tooltip: touch has no hover, and the content is too dense for one.

One deck and one card open at a time, deliberately. A five-deck, 60-card
portfolio would otherwise build hundreds of rows into the DOM on every render.

The engine reads the optimizer's own cardAllocations rather than re-deriving
contention — same discipline as V4, so the matrix can never disagree with the
plan shown in the Advisor.
