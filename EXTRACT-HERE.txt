INKWELL BRASIL — V10: cards per row

Extract over your repo root, then:

  npm run verify
  git add -A && git commit -m "V10: 4-8 cards per row on desktop, fixed 2 on mobile"
  git push

────────────────────────────────────────────────────────────
WHAT CHANGED

The grid was repeat(auto-fill, minmax(230px, 1fr)) — the column count was a
consequence of window width, not a choice. It is now repeat(N, minmax(0,1fr)) with
N from state, and a 4/5/6/7/8 selector sits next to the result count.

minmax(0,1fr) rather than plain 1fr matters: with 1fr, each tile's minimum content
width stops the column shrinking and the grid overflows to the right at 8 columns.

The choice is saved to localStorage (inkwell_collcols) and read at startup, clamped
to 4-8. It is deliberately NOT in userPayload — this is a per-screen preference,
and syncing it would make your phone inherit the desktop's setting.

────────────────────────────────────────────────────────────
BREAKPOINTS

  <= 860px      2 per row, tighter gutter, selector hidden
  861-1240px    3 per row, selector hidden
  > 1240px      your choice applies

The middle band is a judgement call worth knowing about: 8 columns on a 1280px
laptop would give ~130px tiles, too small to read the name or the Normal/Foil
counts. Rather than let the selector produce an unusable result, it steps aside
until there is room for it to mean something.

Hiding the control where it has no effect beats leaving it visible and inert.
